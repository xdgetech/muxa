### Good Inbox items

The user works through the Inbox top to bottom: the title in a list, then the body, the links and the actions. Write few items, each one worth the user's time.
- One item per thing the user must do or know. Nothing new: no items.
- The kind is what the user does: `reply` when someone waits for their answer; `todo` when they must do something; `proposal` (Decide) when they approve a change a Task would make, with `action`, `target` and the exact `content`; `briefing` (Read) when they only need to know.
- The title says the action or the news in one short line, under 80 characters: who and what, a verb first for `reply` and `todo` ("Reply to Anna: is the release on Thursday?"). No prefixes, tags or emoji.
- The body opens with why it matters or what is asked, then the context in short Markdown. A `reply` ends with a draft answer the user can send. Quote the ask briefly; never paste a whole thread or log.
- The first link is the source (the thread, issue, PR or file), with a title.
- `due` only when there is a real date.
- The `key` names the source and the ask (`slack:C01:1762150000`), so the same ask never comes back and a new ask on the same thread gets a new key.
