# muxa roadmap

## Status

Pre-alpha. The daemon, the terminal client, the iPad and iPhone app, the Android app and the Mac app work; the iOS app runs on a real iPad and iPhone, the Android app on phones and tablets. The privacy policy, release settings and the store listings' text are ready (`store/RELEASE.md`). The screenshots of Home and Focus are not taken yet; a human takes them by hand. The app name on both stores, "Muxa: AI agents in tmux", still names tmux. No app is published yet.

Since F5 (2026-11-22), muxa runs on herdr-core only: protocol v1, tmux, muxa for tmux, the v1 Task records, restart and handoff, park and workers' v1 launch paths are gone (ADR 0071).

What works today:
- **Daemon** (`muxa-bridge daemon`, macOS and Linux): a LaunchAgent or a systemd user unit that serves protocol v2 (`protocol/PROTOCOL-v2.md`) on `server.sock` and runs every agent as a herdr-core terminal. `muxa-bridge connect` relays a device's SSH exec to it.
  - Tasks with places: a new folder, branch worktrees and read-only repos, `.muxa/TASK.md`, Claude Code's settings for the other places, plan mode (ADR 0068); connections from the Keychain (ADR 0069).
  - The Inbox of ADR 0066: Capture, the user's order, Later, Done; Review and Failed items from Tasks; Read and Decide items from Routines.
  - Routines on a schedule, each run checked and published (F1, ADR 0026).
  - The Reader of a Task's folder (F2), Task Loops (F3, ADR 0019) and Chat from the agent's own records (F4).
- **Terminal client** (`muxa-cli`): every protocol v2 request, with resume; the reference client and end-to-end harness.
- **iPad and iPhone app** (ADR 0012, 0067): Home (Inbox, Capture, Routines, Needs you) and Focus (the terminals, a terminal at the size of the view, and the Inbox, Reader or Chat as a panel, and the Task Loop), saved hosts with a restricted key and pinned host keys, every shortcut in the README.
- **Mac app** (ADR 0070): the same Home and Focus, "This Mac" over the local socket, menus, a Task's agent with up to three shells as panes in Focus (ADR 0079; the other apps list the shells with the Task), Close Task from a tab, the Reader over the window, keys the user can change and optional Vim window keys (ADR 0078), and a global Capture window. On iOS and the Mac, Settings › Terminal picks the terminal's colors (built in, or imported from iTerm2 or Ghostty) and font; JetBrains Mono and the Nerd Font symbols are bundled, so prompts' icons show (ADR 0080). Not yet on Android. Every app uploads an image or a log into a Task's `.muxa/uploads/` and types its path into the agent (ADR 0081; the Mac also takes a file dropped on a pane).
- **Android app** (ADR 0013, 0029): the same Home and Focus for phones, tablets and foldables, one model per window.
- **Try the Demo** (every app, every build): a built-in v2 server with sample Tasks, Inbox items, Routines, files and conversations; no host and nothing saved. App Review and Play review use it.

## Design

```mermaid
flowchart LR
  apps[iPad, iPhone, Android] -- "SSH exec: muxa-bridge connect<br/>protocol v2 frames" --> D[muxa daemon]
  mac[Mac app] -- "server.sock" --> D
  D -- "JSON-RPC, attach streams, events" --> H[herdr-core]
  D --> F[(.muxa/ in each place,<br/>state dir)]
```

The decisions and their reasons are in `docs/adr/`; the herdr-core facts they rely on are in `docs/findings/session-backends.md`. In short:

- **Transport:** SSH handles authentication and host-key pinning (ADR 0003). The daemon opens no network port: `server.sock` sits in a 0700 directory, mode 0600, and the peer's uid is checked.
- **Protocol:** `protocol/PROTOCOL-v2.md`. Binary frames; JSON control messages on channel 0; one channel per attached terminal with output credit, acknowledged input and resume after a lost connection (ADR 0067).
- **Terminals:** herdr-core owns them, behind the `SessionBackend` trait; `docs/backends.md` says how another multiplexer such as Rex would replace it. muxa starts agents with `muxa.*` labels and finds them again by those labels; it never changes a terminal it did not start. A terminal takes the size of its last active viewer.
- **State:** each Task's state lives in its working place (`.muxa/TASK.md`, `.muxa/loop.json`, `.muxa/CHECK.md`); Routine state and the Inbox live in the state dir. A restarted daemon goes on from the files.
- **Agent state** is what the program reports with OSC 7501, never a guess. Chat reads the agent's own records through its adapter (`docs/agents.md`).

### Daemon internals

- `muxa-server` owns the protocol: sessions, attachments with a 256 KiB resume buffer for 10 minutes, the Reader's follow loop, chats and `watch`. It reaches the host only through the `Host` trait, which `muxa-bridge`'s `v2::BridgeHost` implements.
- Long-running watches on herdr-core's change stream: Task agents for Failed items, Routine run terminals, and Task Loops. Each one starts again, with growing waits, when herdr-core goes away.
- Blocking work (git, files, the Keychain, checks) runs on the blocking pool; checks run in their own process group and are killed at their timeout.

### Rejected

- Attaching a normal tmux client, as Multiplex and Remux do (ADR 0001, 0020); later, tmux itself (ADR 0067, 0071).
- A shared Rust client core through UniFFI (ADR 0013). Swift and Kotlin each keep their own v2 client; the real server on the fake backend tests both.

## Risks

- **A run or a Task in a folder Claude Code does not trust** waits on the trust dialog: a Routine run until its 2 h limit. Trusting the workspace root once covers its folders.
- **The SSH key can run a shell** unless it is restricted. `SECURITY.md` shows the `authorized_keys` restriction, and the app sets it up.
- **A check runs a command with no one watching.** `[workspace.loop]` in `workspaces.toml` decides per workspace which commands may run (`SECURITY.md`).
- **herdr-core is pre-1.0.** `crates/muxa-backend`'s contract suite and `scripts/repro/herdr-core-api.sh` catch a change in what muxa relies on.
